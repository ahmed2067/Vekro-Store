# VEKRO STORE

متجر عربي RTL مبني باستخدام Node.js 20+ وExpress.

## المزايا الموجودة في الكود
- واجهة متجر متجاوبة مع البحث والتصنيفات والسلة.
- طلبات دفع عند الاستلام تُسجّل محليًا برقم طلب.
- صفحة تتبع الطلب باستخدام رقم الطلب ورقم الهاتف.
- لوحة إدارة على المسار `/admin` لتسجيل دخول المدير وإدارة المنتجات المحلية وتغيير حالة الطلبات.
- استيراد منتجات Safka من خلال وسيط خادمي عند ضبط المسار والمفتاح الصحيحين.

## إعدادات المدير والاستضافة
اضبط هذه القيم في إعدادات Environment Variables لدى الاستضافة، ولا تضعها في ملفات الواجهة أو GitHub:
- `SESSION_SECRET`: قيمة عشوائية طويلة لا تقل عن 32 حرفًا.
- `ADMIN_EMAIL`: بريد المدير.
- `ADMIN_PASSWORD`: كلمة مرور قوية وفريدة.
- `DATA_DIR`: مسار تخزين دائم قابل للكتابة.
- `NODE_ENV=production`

مثال توليد سر عشوائي محليًا: استخدم مدير كلمات مرور موثوقًا أو مولّدًا محليًا؛ لا ترسل السر في المحادثات.

## تشغيل محلي
1. ثبّت Node.js 20 أو أحدث.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env` وأدخل القيم محليًا.
4. نفّذ `npm start`.
5. افتح `/admin` للدخول إلى لوحة الإدارة.

## Safka
اضبط `SAFKA_API_BASE_URL` و`SAFKA_API_KEY` و`SAFKA_PRODUCTS_PATH` من وثائق حساب Safka الرسمية. لا تضع المفتاح في HTML أو JavaScript للمتصفح. لم يتم تفعيل إنشاء طلبات داخل Safka لأن مسار الإنشاء وبنية الطلب لم يتم التحقق منهما بعد.

التوثيق: https://public-api-docs.safka-eg.com/

## ملاحظات مهمة قبل استقبال عملاء حقيقيين
- التخزين الحالي JSON محلي، وليس قاعدة بيانات إنتاجية؛ يجب إعداد قرص دائم، والأفضل الانتقال إلى قاعدة بيانات مُدارة قبل الإطلاق العام.
- جلسات المدير محفوظة في ذاكرة العملية وتنتهي عند إعادة تشغيل الخادم.
- يجب اختبار الحماية، الاستعادة، النسخ الاحتياطي، الأسعار والمخزون، ورسائل التأكيد قبل الإطلاق.
- المنتجات المحلية التي تُضاف من لوحة الإدارة تظهر عندما لا يكون استيراد Safka مهيأً. عند تفعيل Safka، تعرض الواجهة بيانات Safka.
- دفع الطلبات حاليًا عند الاستلام فقط، ولا يوجد بوابة دفع إلكتروني مفعّلة.

## النشر
رفع الملفات إلى GitHub لا ينشر الموقع وحده. يلزم ربط المستودع باستضافة Node.js وضبط متغيرات البيئة والتخزين الدائم. لا يوجد رابط منشور للمتجر حتى الآن.
